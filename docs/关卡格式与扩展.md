# 关卡格式 与 扩展方式

## 一、关卡 JSON

编辑器「导出 JSON」出来的就是这个格式。默认值全部省略，所以文件很短、也好手改。

```jsonc
{
  "name": "第 1 关",
  "w": 8,          // 宽（格）
  "h": 6,          // 高（格）
  "note": "",      // 备注（可选）
  "cells": [ ... ] // 长度必须是 w*h，行优先（先第一行从左到右，再第二行）
}
```

每个格子的写法（三种字段都可选）：

```jsonc
{}                                                  // 空地
{ "t": 1 }                                          // 墙（老数据兼容用；编辑器已经画不出墙了）
{ "goal": "square" }                                // 方形目标  ("circle" = 圆形目标)
{ "item": { "k": "square" } }                       // 正方形    ({"k":"circle"} = 圆形)
{ "item": { "k": "device", "type": "push", "s": "R" } }  // 一台朝右的推动活塞
{ "goal": "square", "item": { "k": "square" } }     // 正方形 + 目标（开局就归位）
```

目标可以放在任何格子上（包括最外圈），图形/设备也可以直接放在目标上（开局就在位的状态）。
**墙已经取消**：新一轮的关卡都是矩形，棋盘外沿就是天然边界，编辑器里没有墙笔刷、改尺寸也不会再铺外墙。
只有老存档 / 老 JSON 里可能还留着 `t: 1`；导入时墙仍然能正常读取和渲染，**墙上不能放东西**（发现就自动把墙改成地板并在提示里告诉你）。

### 设备 `type` 与状态 `s`

| type | 名称 | `s` 的取值 |
| --- | --- | --- |
| `push` | 推动活塞 | `U` `R` `D` `L` |
| `pull` | 拉动活塞 | `U` `R` `D` `L` |
| `spush` | 强力推动活塞 | `U` `R` `D` `L` |
| `spull` | 强力拉动活塞 | `U` `R` `D` `L` |
| `vpush` | 可变活塞 | `U:push` `U:pull` `R:push` `R:pull` `D:push` `D:pull` `L:push` `L:pull` |
| `swap` | 交换器 | `ud` `lr` `ul_ur` `dl_dr` `ul_dl` `ur_dr` |
| `switch` | 换向交换器 | `v`（上下） `h`（左右） |
| `rotate` | 旋转器 | `cw`（顺时针） `ccw`（逆时针） |
| `modifier` | 修改器 | `U` `R` `D` `L` |

方向：`U` 上、`R` 右、`D` 下、`L` 左（屏幕坐标，y 向下）。

导入时会自动体检：宽高非法、`cells` 数量不对、设备类型/状态不认识、墙上有东西 —— 都会被**修复**并在界面上列出修正内容（不会因为一个错字整关卡打不开）。

## 二、在 Node / 代码里造关卡（测试用）

`MPCore.buildLevel()` 支持 ASCII 地图，写测试最省事：

```js
const L = MPCore.buildLevel({
  name: '示例', w: 7, h: 5,
  map: [
    '#######',
    '#.....#',
    '#..Ss.#',    // '#'=墙  '.'=空地  's'=正方形  'c'=圆形  'S'=方形目标  'C'=圆形目标
    '#.....#',
    '#######',
  ],
  devices: [ { x: 5, y: 2, type: 'push', s: 'L' } ],
  solution: [[5, 2]],    // 可选：记录解法（点击序列，测试会用它验证可解）
});
```

## 三、加一种新设备

只需要动三个地方（框架就是为这个准备的）：

### 1. `js/core.js` — 注册设备（数据）

```js
D.magnet = {
  key: 'magnet', name: '磁铁', color: '#f97316', glyph: 'push',
  tip: '把正前方 3 格的物品吸过来。',
  states: MP.DIR_LIST.slice(),                 // 可选状态
  stateName: function (s) { return MP.DIR_NAME[s]; },
  rotate: MP.nextDirCW,                        // 修改器顺时针转它时变成什么状态
  piston: false,                               // 是否属于「活塞家族」（换向交换器会不会反转它）
};
MP.DEVICE_ORDER.push('magnet');                // 放进编辑器调色板
```

> `glyph` 决定用哪套图标：`push` `pull` `spush` `spull` `vpush` `swap` `switch` `rotate` `modifier`。
> 想要新图标就在 `js/render.js` 的 `drawDirIcon()` 里加一个分支。

### 2. `js/rules.js` — 写判定（纯推演）

在 `R.computeAction()` 的 `switch (type)` 里加一个 case，返回 `ok({ moves, states, affects })` 或 `fail(原因, affects)`：

```js
case 'magnet': {
  const c3 = walk(L, x, y, s, 3), i3 = walkIdx(L, x, y, s, 3);
  const c1 = walk(L, x, y, s, 1), i1 = walkIdx(L, x, y, s, 1);
  const affects = [i1, i3];
  if (!c1 || !c3) return fail('越出棋盘', affects);
  if (c1.t === WALL || c3.t === WALL) return fail('前方是墙', affects);
  if (c1.item) return fail('紧邻格被占用', affects);
  if (!c3.item) return fail('前方 3 格没有物品', affects);
  return ok({ moves: [{ from: i3, to: i1, item: c3.item }], affects: affects });
}
```

`moves` 里的每一项是 `{ from, to, item }`（格子下标 + 物品对象），可附加：

| 附加字段 | 动画效果 |
| --- | --- |
| （无） | 直线滑过去 |
| `arc: true` | 沿外鼓弧线互相绕过（交换用） |
| `orbit: { cx, cy, from, cw }` | 绕 `(cx,cy)` 走 1/4 圆弧（旋转器用） |
| `dist` / `strong: true` | 距离越远越慢 + 残影拖尾 |

`states` 用来改设备自身/目标的状态：`{ at: 格子下标, s: 新状态, from: 旧状态 }`。
`from` 必填 —— 动画要靠它算旋转过渡。

### 3. `js/render.js` — 画图标（可选）

复用 `push` 那套就什么都不用改；要专属图标就在 `drawDirIcon()` 里加分支。
徽标（右下角那个小字）在 `R.drawDeviceGlyph()` 的 `badge` 一行里加。

改完跑一次 `run-tests.cmd`，规则测试会覆盖到基础判定。

## 四、框架 API 速查

```js
MPCore.newLevel(w, h, name)          // 空关卡
MPCore.cloneLevel(L)                 // 深拷贝
MPCore.at(L, x, y) / idx / itemAt    // 取格子 / 下标 / 物品
MPCore.buildLevel(spec)              // 用 ASCII 地图造关卡（'#' 仍然是墙，测试夹具用）
MPCore.analyze(L)                    // 数量统计 + 体检警告
MPCore.DEVICES / DEVICE_ORDER        // 设备目录

MPRules.computeAction(L, x, y)       // 纯推演：{ ok, reason, moves, states, affects, beam, note }
MPRules.applyMoves(L, act)           // 只落位移
MPRules.applyStates(L, act)          // 只落状态
MPRules.applyAll(L, act)             // 一起落
MPRules.activate(L, x, y)            // 推演 + 立即落子（无动画时用）
MPRules.isWin(L) / misplaced(L)      // 通关判定 / 还有几个没归位

MPFx.add({...}) / update(dt) / whenIdle() / timeScale
MPSfx.play('push')                   // 播放一个合成音效（无 AudioContext 时返回 false）
MPSfx.setEnabled(bool) / toggle()    // 音效开关（记在 localStorage）
MPRender.draw(ctx, L, view, opts)    // opts: { fx, hover, preview, ghost, selected }
MPRender.makeGlyphCanvas(type, s, px)// 拿一张设备小图（调色板/帮助面板用）
MPRender.makeThumbCanvas(L, px)      // 选关卡片用的缩略小地图
MPLibrary.blank(w,h,name,chapterId) // 空白关卡（矩形，没有外墙）
MPLibrary.autoName(chapterId)        // 自动关卡名，形如 "1-3"
MPLibrary.sandbox()                 // 机制沙盒
MPLibrary.chapters()                // [{id,name,levels:[{id,name,w,h,cleared}]}]
MPLibrary.list() / get / put / remove
MPLibrary.addChapter / renameChapter / removeChapter
MPLibrary.moveLevel(levelId, chapterId, index) / swapLevels(a,b)
MPLibrary.indexOf(levelId)          // {chapterIndex,index,label:'1-2'}
MPLibrary.nextLevel(id) / prevLevel(id)
MPLibrary.isCleared(id) / markCleared(id) / clearedCount() / resetProgress()
MPLibrary.serialize / importText / normalize / download

MPApp.startLevel(id)                // 开始玩某一关
MPApp.gotoSelect()                  // 回到选关界面
MPApp.gotoLevel(+1 / -1)            // 上一关 / 下一关
MPApp.newLevel(chapterId)           // 在某个大关里新建关卡并入库（自动命名 1-N）
MPApp.openLevelInEditor(id)
MPApp.playtest()                    // 用编辑器当前内容开局（S 键）
MPApp.backFromPlay()                // 试玩中返回编辑 / 游玩中返回选关（B 键）
MPApp.saveAndNext()                 // 保存并新建同尺寸下一关（Ctrl+S）
MPApp.step(dt)                      // 手动推进一帧（自动化测试用，不依赖 rAF）
```
