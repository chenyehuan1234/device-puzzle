# 规则细节（实现版本）

> 这份文档描述的是**代码里真实生效的判定**，设计关卡时以它为准。
> 凡是「我做了取舍」的地方都标了 ⚠️，想改直接说，或者在标注的文件里改一行。
>
> **关于墙**：这一版已经把「墙」从编辑器里彻底去掉（所有地图都是矩形，棋盘外沿就是边界）。
> 下面凡是写「是墙」的地方，现在一律读作「棋盘外沿（越界）」；规则层仍然支持墙这种地形，
> 只为兼容老关卡和导入的 JSON，编辑器里造不出来了。

## 0. 通用

| 项 | 规则 |
| --- | --- |
| 触发方式 | 鼠标点一下设备 = 触发一次；设备不需要能量、没有冷却 |
| 棋盘外 | **就是边界**：越界一律视为阻挡（与以前的墙完全等价） |
| 墙 | **已取消**：新关卡画不出墙；老关卡里的墙仍按静止地形处理（不能推、不能换、不能被旋转、不能被修改器作用） |
| 设备 | **也是操作对象**：可以被推、被拉、被交换、被旋转、被修改器改 |
| 冲突 | **全有或全无**：任何一格冲突 → 这次点击【整体无效】，棋盘一格都不变 |
| 通关 | 所有正方形都在方形目标上、所有圆形都在圆形目标上（步数不限） |

游戏的判定顺序永远是：先 `computeAction()` **纯推演**（不改棋盘），只有 `ok === true` 才落子。
所以「点击了但什么也没发生」= 推演失败，不会有半截状态。

## 1. 交换器 `swap`（6 种朝向）

设备**自身不动**，交换相对它中心对称的那两格里的物品（两格都可以是空的，也可以有设备）。

| 朝向 | 交换的两格 |
| --- | --- |
| `ud` 上下 | 正上 ↔ 正下 |
| `lr` 左右 | 正左 ↔ 正右 |
| `ul_ur` 上斜 | 左上 ↔ 右上 |
| `dl_dr` 下斜 | 左下 ↔ 右下 |
| `ul_dl` 左斜 | 左上 ↔ 左下 |
| `ur_dr` 右斜 | 右上 ↔ 右下 |

判定：

- 两格中任意一格越界 / 是墙 → **失败**
- 两格都空 → 失败（没有可交换的东西）
- 只反转朝向的效果不在这里（那是 5 号换向交换器）

---

## 2. 旋转器 `rotate`（顺时针 / 逆时针）

把**上下左右四格**里的内容整体转一格，设备自己是轴心、不动。

- 顺时针：上 → 右 → 下 → 左 → 上
- 逆时针：上 → 左 → 下 → 右 → 上
- 四格里任意一格越界 / 是墙 → **整体失败**（四格都不动）⚠️（按你选的：冲突就一律不能动）
- 四格里的**设备**也会被转过去（朝向字符串不变；要改朝向得用修改器或换向交换器）
- 四格都空时点击 = 空转（不算失败，但没有变化）

---

## 3. 推动活塞 `push`

把**正前方 1 格**的物品向前推 1 格。

- 前方是墙 / 越界 → 失败
- 前方为空 → 失败
- 前方第 2 格是墙 / 越界 / **有物品** → 失败（一次只能推一个物品）
- 可以在目标格上，可以推设备

---

## 4. 拉动活塞 `pull`

把**正前方 2 格**的物品拉到**正前方 1 格**。

- 紧邻格（前方 1 格）被占用 / 是墙 / 越界 → 失败
- 前方 2 格为空 / 是墙 / 越界 → 失败
- **它永远不会推动任何东西**

---

## 5. 换向交换器 `switch`（上下 / 左右）

交换规则和 1 号完全一样：

- `v` 上下型：交换正上、正下两格
- `h` 左右型：交换正左、正右两格

额外效果：**被这次交换挪动的活塞家族设备，朝向反转**（上下互换、左右互换）。

- 活塞家族 = 推动活塞 / 拉动活塞 / 强力推动 / 强力拉动 / 可变活塞
- 可变活塞反转时**保留推/拉模式**（例如 `R:pull` → `L:pull`）
- ⚠️ 其它设备（旋转器、交换器、修改器）**只换位、不反转朝向**（严格按你写的「对于活塞或者拉动…朝向相反」）

---

## 6. 可变活塞 `vpush`

`推模式` 时完全等同 3 号推动活塞；`拉模式` 时完全等同 4 号拉动活塞。

点击后：

- 动作**成功** → 执行动作，并**切换模式**（推→拉、拉→推）
- 动作**失败** → 什么都不发生，**连模式都不切**（推不动 / 拉不动时点击它毫无变化）

---

## 7. 强力推动活塞 `spush`

把**正前方 1 格**的那一个物品一直往前推，**推到它能到的最深处**：

- 正前方为空 / 是墙 / 越界 → 失败
- 停靠条件：**前方下一格是墙、到边界、或者有任何一个东西（设备 / 正方形 / 圆形）** → 停在它前面一格
- **一路上别的东西都不动**，被推的只有紧邻的那一个物品
- 如果它一格都推不动（前面紧贴着墙 / 设备 / 图形）→ 失败（整体不动）
- 停靠的判定与「打不打得动」无关：哪怕挡路的那个东西本身可以被推动，这里也不会去推它

---

## 8. 强力拉动活塞 `spull`

沿朝向找**最近的物品**，直接拉到**正前方 1 格**。

- 紧邻格被占用 / 是墙 / 越界 → 失败
- 沿途遇到墙 → 失败（拉不过来）
- 找到的第一个物品可以是图形，也可以是设备
- 只拉最近的那一个，后面的不动

---

## 9. 修改器 `modifier`

沿朝向**一直往前找第一个物体**（距离不限）：

- 前方什么都没有 → 失败
- 遇到**墙** → 失败（被挡住）
- 第一个物体是**正方形 / 圆形** → 失败（不作用）
- 第一个物体是**设备** → **顺时针把它转一格**，动作成功

「顺时针转一格」对各种设备意味着：

| 被改的设备 | 结果 |
| --- | --- |
| 推动 / 拉动 / 强力推动 / 强力拉动 | 上→右→下→左→上 |
| 修改器 | 上→右→下→左→上（**修改器可以改修改器**） |
| 可变活塞 | 只转方向，推/拉模式不变 |
| 换向交换器 | 上下 ↔ 左右 |
| 交换器 | 按真实几何顺时针 90°：上下↔左右；上斜→右斜→下斜→左斜→上斜 |
| 旋转器 | 顺时针 ↔ 逆时针（旋转器没有朝向，只有转向）⚠️ |

---

## 10. 通关判定

```
每个正方形所在格 goal === 'square' 且 每个圆形所在格 goal === 'circle'
且场上至少有一个图形
```

- 设备、墙踩在目标格上不影响；只有图形参与判定
- ⚠️ 当前是「图形全部归位就通关」；如果目标数量比图形多，多余的空目标**不需要**填。
  编辑器体检会提示数量不一致。
  想改成「所有目标都必须被填满」：在 `js/rules.js` 的 `R.isWin()` 里加上反向检查即可，例如

```js
// 额外要求：每个目标格上都必须有同形状图形
for (var i = 0; i < L.cells.length; i++) {
  var c = L.cells[i];
  if (c.goal && (!c.item || c.item.k !== c.goal)) return false;
}
```
