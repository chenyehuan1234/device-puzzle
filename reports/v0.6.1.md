# v0.6.1 · 2026-09-19 · 修「换了关卡库，页面还是旧关卡」

## 1. 这次要解决什么

- 老板原话：**「我在这里刷新了，结果显示的还是旧关卡」**（指线上地址 <https://chenyehuan1234.github.io/device-puzzle/>）
- 目标：找出为什么换了 72 关的库、刷新还是 45 关，并让「更新关卡库」这件事真的能生效。
- **不做什么**：不改关卡数据本身、不动游戏规则、不动编辑器画关功能。

## 2. 根因

**内置关卡包的身份标签太粗，分不出「同一天导出的两份包」。**

原来的身份是 `包名@导出日期`，而导出日期只精确到**天**（`new Date().toISOString().slice(0, 10)`）。
所以新旧两份包的身份**一字不差**，都是：

```
我的关卡库@2026-09-19
```

于是启动逻辑 `Lib.seedDone() !== tag && Lib.count() === 0` 永远不成立 —— 浏览器认为
「这一包已经装过了」，既不装入也不提示，一直用着盘古那一份 45 关。

**证据**（换库前后各取一次，两个字段完全一样）：

| | `name` | `exportedAt` | 拼出来的标签 | 关卡数 |
| --- | --- | --- | --- | --- |
| 旧库 | 我的关卡库 | 2026-09-19 | `我的关卡库@2026-09-19` | 45 |
| 新库 | 我的关卡库 | 2026-09-19 | `我的关卡库@2026-09-19` | **72** |

## 3. 改了什么

按「用户看得见的行为」写：

| 需求 | 结果 | 怎么验证的 |
| --- | --- | --- |
| 关卡包身份要能分辨内容 | 身份改成 **`包名@导出日期#关数.内容哈希`**，哈希覆盖 chapters 结构 + levels 整体数据 | 单测：改掉一关的名字 → 指纹就变了 |
| 换了库要**告诉玩家** | 本机已有内容、且内置包不是上次那份 → 选关界面挂出**「⚡ 更新到新版（45 关 → 72 关）」**提示条 + 顶栏按钮变「⚡ 更新内置关卡包」 | 端到端：旧 profile 打开新版 → 提示条出现，仍显示 45 关（没有被偷偷换掉） |
| 一键换过来 | 提示条上的按钮点一下 → 整库换成内置包，**通关进度按关卡 id 保留** | 端到端：真实点击后 `45 → 72`，5 个大关，卡片 45 → 72 张 |
| 换之前别丢数据 | 替换前**自动备份**本机内容；选关界面出现「有一份换库前的备份 … 恢复这份备份 / 删掉备份」 | 端到端：点完更新后备份条显示 `45关 / 更新到内置关卡包前`；单测覆盖 存→读→恢复→删 |
| 不想换就别烦我 | 提示条第 3 个按钮「先不动」→ 只记下「已处理」，库一个字节都不动 | 单测：`Lib.count()` 不变，`seedDone` 写入新指纹 |
| 有别的方式保留本机内容 | 保留原「导入内置关卡包（副本，不会覆盖）」按钮 | 探针 140 项全过 |
| 别误导 | 说明条文案区分「这一份自带的包」和「这一份自带的是**新版**」 | 端到端抓 DOM 看文案 |

## 5. 规则 / 交互变化

- **关卡包 JSON 格式没变**（还是 `{format, version, name, exportedAt, chapters, levels}`），
  老包照样能读 —— 内容指纹是**运行时算出来的**，不需要包里多存字段。
- 交互变化：以前「本机有内容 → 什么都不说」，现在「本机有内容且内置包变了 → 明确提示可更新」。
  **默认行为仍然是「不自动覆盖」**，只是把选择权交给玩家。
- 我自己做的判断：
  - ❓ 顶栏那个按钮改成「有新版就更新，否则导入副本」的两用按钮。原来只做「导入副本」。
  - ❓ 备份存在 `localStorage`（键 `mp.backup.v1`），只留**最近一份**，不进关卡库本身。够用但不做多版本历史。

### 端到端复现（本地静态服务 + 无头 Chrome，真实点击）

先把「45 关旧库」和「72 关新库」各打一份单文件版，用同一个浏览器 profile 走一遍：

| 步骤 | 结果 |
| --- | --- |
| ① 干净浏览器打开旧版 | 45 张卡片，无提示条（正常自动装入） |
| ② **同一个浏览器**打开新版 | 进度仍显示「共 45 关」；出现 `seed-note is-update`：**「这一份自带了新版关卡包「我的关卡库」：5 个大关 / 72 关。你浏览器里还存着旧的一份（45 关）…要更新得你点一下」**；顶栏按钮 = `⚡ 更新内置关卡包` |
| ③ 真实点击「⚡ 更新到新版」 | `before=45 → after=72`，`chapters=5`，卡片 `45 → 72`，进度条变「共 72 关」，备份 `45关/更新到内置关卡包前`，`seedDone=我的关卡库@2026-09-19#72.…` |
| ④ 再刷新一次 | 72 张卡片，**不再提示更新**，备份条还在（可以退回 45 关） |

新增/修改的用例（共 51 项）：

- `bundleFingerprint` 稳定 / 内容变则变；「包名+日期相同但内容不同」的分辨
- `bundleCount` 只数「引用了且数据真的在」的关
- `replaceWith` 报告换库前关数、替换后通关进度按 id 保住
- `saveBackup / backupInfo / restoreBackup / clearBackup` 全链路
- `clearSeedDone` 能重新触发更新提示
- `applySeedUpdate` 确认框点「取消」→ 什么都不做
- 选关界面三种提示条（更新 / 备份 / 普通）+ 三个按钮文案 + 「先不动」不改库

## 7. 已知问题 / 取舍

- 端到端那套（本地起静态服务 + 同源 iframe 触发点击）是**临时验证脚本，没有进仓库**。
  以后要回归「换库提示」这条链路，跑 `node tests/ui.smoke.js` 第 12 节 + 探针即可覆盖绝大部分。

- 关卡数据里那 7 关死局（1-5 / 1-7 / 4-2 / 4-5 / 4-8 / 4-17 / 5-2）**这次没动**，仍在。
