## 2. 问题 1：不是读你的硬盘，是浏览器的规矩

**结论：同一个浏览器里，所有本地（`file://`）页面共用一份存档（localStorage）。**

`index.html`、`dist\机关谜题.html`、`dist\带关卡-xxx.html` 在你机器上是**同一份 `mp.library.v1`**，
所以打包文件打开后读到的是你**本机当前**的关卡库（包含你后来画的所有关）——这是浏览器的行为，
不是打包脚本去读你的磁盘。发给别人时对方存档是空的，所以「第一次打开自动装内置包」是正常的。

**但这件事确实很难自己想明白，所以我做了三件事**：

| 做了什么 | 效果 |
| --- | --- |
| 选关界面顶部新增**蓝色说明条** | 当「本机已有内容 + 这一份自带关卡包」时显示：<br>「这一份自带了关卡包「X」：3 个大关 / 25 关。不过你这个浏览器里已经有 37 关了自己的关卡（同一个浏览器里所有本地页面共用一份存档），所以内置包没有覆盖它 —— 下面显示的是你本机的内容。」<br>条上带 **「导入内置关卡包（副本，不会覆盖）」** 按钮，和一句提示 |
| 提示「怎么当新玩家试玩」 | 说明条里直接写了：**用隐私 / 无痕窗口打开这一份** |
| README 加了一节 | 《为什么我在自己电脑上打开打包好的文件，看到的是我自己的关卡？》把三种场景（自己试玩 / 发给别人 / 想导入内置包）都写清楚了 |

真浏览器验证：说明条会出现、写出包名、解释了原因、按钮存在（探针 140 项）。

## 3. 问题 2：批处理被 cmd.exe 拒了（这个是真 bug）

**复现**（我这边同样闪退）：

```
> cmd /c build.cmd
'�关卡包.json' is not recognized as an internal or external command
'ho.' is not recognized as an internal or external command
'hrome）' is not recognized as an internal or external command
```

**原因**：`build.cmd` / `run-tests.cmd` 是我用 UTF-8 + **LF 换行**写的批处理，还带着
多行 `if (...)` 块和中文。cmd.exe 解析不了这种文件（LF 换行 + 中途 `chcp` + 多字节字符），
于是脚本没跑几行就报错退出 —— 双击时表现就是「黑窗闪一下」。

**修法**：

- `.cmd` 变成**纯 ASCII + CRLF** 的最小壳子：只负责 `chcp 65001`、挑 PowerShell（优先 `pwsh`，退回 `powershell`）、
  调用 `tools\build.ps1`、`pause`（保证窗口不会一闪而过）、把退出码带出去
- 真正的活交给新的 **`tools/build.ps1`**：检查 node、确定关卡包、执行打包、跑单文件自检，
  每步都有中文说明，出错会停在窗口里
- `run-tests.cmd` 同样处理（ASCII + CRLF + 无括号块 + 末尾 pause）
- 新增 **`tests/packaging.test.js`**（44 项）**把这条教训钉死**：`.cmd` 必须 CRLF、纯 ASCII、含 `pause`、
  没有多行括号块；两个自检脚本必须带 `--user-data-dir`；`index.html` 的引用必须都存在且顺序正确；
  `.gitattributes` 里 `*.cmd` 必须是 CRLF
- `git status` 里 `.cmd` 现在是 CRLF（`.gitattributes` 早写好了 `*.cmd text eol=crlf`，只是工作区没转过来）

**验证**：`cmd /c build.cmd` 现在完整跑通（打包 + 13 项自检），退出码 0。

## 4. 顺手澄清（不是 bug，但容易误解）

- 你的 `关卡库.json` 里又出现了「探针大关」：我在 v0.5.0 已经堵住了源头（自检用临时 profile），
  这是**之前**就留在浏览器里的旧数据，你每次重新导出都会把它一起带出来。
  **一劳永逸的办法**：在编辑器左边栏点中「探针大关」→「删除选中大关」。
  我这次也再把 `关卡库.json` 清了一遍（37 → 36 关，只删那一个大关）。
- `tools/cleanup-library.html` 现在是**可交互**的：用浏览器直接打开它 → 看到本机关卡库清单 →
  点按钮删掉可疑大关（带确认），比命令行更直观。

## 7. 已知问题 / 取舍

- 「同一个浏览器共用存档」是浏览器行为，我只能做到**说清楚 + 给一键导入**，没法让打包文件忽略本机存档。
- `关卡库.bak.json` 是清理工具的备份（已在 `.gitignore` 里），确认没问题后可以删。
- 如果你希望打包文件支持「强制以新玩家身份启动」（比如加个 `?fresh` 参数清空再装），说一声，可以做。

## 8. 下一步建议

1. **每关最少步数**：你用解法录制的数据当基准，选关卡片上显示「最少 N 步 / 你的 M 步」
2. **重做 Ctrl+Y**、**框选 / 矩形填充 / 区域复制粘贴**、**WASD 键盘光标**
3. **体检增强**：粗判有没有图形被彻底堵死
