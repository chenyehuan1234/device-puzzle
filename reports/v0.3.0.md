# v0.3.0 · 2026-09-19 · 四个拐角交换器 + 解法录制与一键回放

## 1. 这次要解决什么

1. **再加四种交换器：上右、上左、下左、下右** —— 也就是「夹住设备某个角的两格」互换
   （上 ↔ 右、上 ↔ 左、下 ↔ 左、下 ↔ 右），这样交换器凑齐 12 种
2. **把解法录制做了**：试玩通关时把点击序列记进关卡，之后能一键回放，确认「我画的这关确实可解」

**不做什么**：不改任何已有设备的判定，不改通关规则，不改关卡数据格式（只是 `swap` 多了 4 个合法状态值，并开始使用一直空着的 `solution` 字段）。

## 2. 改了什么

| 需求 | 结果 | 怎么验证的 |
| --- | --- | --- |
| 1 四个拐角交换器 | `swap` 从 8 种扩到 **12 种**：`u_r`（上↔右）、`u_l`（上↔左）、`d_l`（下↔左）、`d_r`（下↔右）。图标仍然自动复用「两条指向要交换格子的线段」，所以拐角换看起来就是两条互相垂直的短箭头 | 规则测试：12 种方位两两不同、**4 种中心对称 + 4 种拐角 + 4 种贴边**分类、`u_r` 交换上和右且不碰两个角、单侧有东西也能换；探针在真实浏览器里确认调色板出现 4 个拐角按钮 |
| 1 修改器兼容 | 拐角交换器顺时针转一格 = 上右→下右→下左→上左→上右（真实几何） | 规则测试：4 条 `修改器：swap u_r → d_r` … |
| 2 解法录制 | 游玩时每次成功点击都记进 `playLog`（撤回 / 重开会同步回退）；通关横幅上出现「💾 记下这个解法（N 步）」；点了就写进关卡的 `solution` | 冒烟：点击 → `playLog === [[5,2]]` → `saveSolution()` → 库里读到解法；撤销 → 记录退一步；重开 → 清空 |
| 2 一键回放 | 右栏新增「解法录制」面板：显示已记录步数 + 「▶ 回放解法」「清空解法」。回放会重新开局、按原节奏重放每一步，跑完告诉你「✓ 确实可解」或「✗ 回放完了但没通关」 | 冒烟：逐步驱动 `replayStep()` 走到 `done` 且真的通关；探针：真浏览器里点按钮跑完整个回放并弹出通关横幅 |
| 2 过期解法 | 回放中途遇到冲突会停下并报「回放到第 N 步就冲突了（原因）」 | 冒烟：把解法改成 `[[0,0]]`（空地）→ `replayStep()` 返回 `fail`，状态清空不崩 |
| 2 解法进 JSON | `solution` 现在会跟着序列化导出；导入时会校验每一步的坐标，越界/格式错的丢掉并提示 | 冒烟：JSON 往返保留解法；`solution:[[0,0],[9,9],"x",[1]]` → 只剩 `[[0,0]]` 且有警告 |
| 附带 | 回放**不记通关进度**（验证≠玩过）；体检里多一行「✓ 已记录解法：N 步」；副标题显示「解法 N 步」；版本号 0.3.0；单文件版 165.8 KB | 探针：体检 / 解法面板文字断言、单文件自检 9 项 |

## 4. 规则 / 交互变化

- 交换器 12 种，老 8 种判定一个字没变；`swap` 的合法 `s` 多了 `u_r` `u_l` `d_l` `d_r`（老存档不受影响）。
- 关卡 JSON 新增可选的 `solution`（点击序列）。**不写也能用**，只是没有回放功能。
- 「拐角交换器」这个名字是我按几何起的 ❓：`u_r` = 夹住右上角的两格（上 与 右）互换。
  如果你心里的「上右」是别的意思（比如「右上角 ↔ 右下角」那种），说一声，改 `SWAP_PAIRS` 四行就行。

## 6. 已知问题 / 取舍

- 回放的节奏由 `App.animOn ? 240ms : 30ms` 控制，长距离强力推动会稍慢；想更快可以关掉顶栏「动画」。
- 回放依赖画面刷新推进动画（rAF）。**切到别的标签页时回放会停在那儿**，切回来会继续 —— 和手动游玩的表现一致。
- 录制只记「成功生效的点击」，冲突的点击不进解法（这是有意的：解法是可解路径）。
- 单文件版 165.8 KB（没压缩）。
